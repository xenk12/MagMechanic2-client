# Create: Connected — выравнивание нагрева горизонтального котла

Статус: инструкция и вспомогательный патч, **не применены к рабочему серверу автоматически**.  
Цель: убрать специальный штраф к нагреву Fluid Vessel относительно вертикального Fluid Tank Create, не меняя другие характеристики.  
Целевой модпак: Minecraft 1.21.1 / NeoForge / Create 6.0.10 / Create: Connected 1.2.0 (проверьте реальные версии на сервере).

## Настройка

В серверном файле `create_connected-server.toml` найти существующий параметр и заменить **только** его значение:

```toml
vesselHeatMultiplier = 1.0
```

Значение по умолчанию — `0.5`, то есть специальный штраф к нагреву горизонтальных котлов. `1.0` снимает этот штраф.

**Не изменять:** `vesselBoilerStressMultiplier` (отвечает за выдаваемую кинетическую мощность, по умолчанию 0.8125), `vesselMaxLevel`, рецепты, формы баков, Java-классы. Игрок запросил *только нагрев*, не повышение мощности. Одинаковый множитель не гарантирует, что котлы разной геометрии и с разным количеством горелок станут идентичны.

## Куда вносить изменение, чтобы оно реально работало

**Нужен конфиг СЕРВЕРА, а не этот файл на GitHub.** Его фактический путь зависит от сервера/загрузчика/мира. Проверьте логи и используемую конфигурацию; типичный путь в Forge/NeoForge:

`<server>/<world>/serverconfig/create_connected-server.toml`

В некоторых установках используется путь `<server>/config/create_connected-server.toml`; определите реально загружаемый файл. `defaultconfigs` влияет преимущественно на новые миры, а не заменяет конфиг уже существующего мира.

1. Остановить сервер в обычном порядке.
2. Сделать резервную копию реального TOML.
3. Найти `vesselHeatMultiplier` (должен встречаться один раз), изменить только значение с `0.5` на `1.0`.
4. Запустить сервер и проверить, что конфиг не перезаписан, нет ошибок загрузки и горизонтальный котёл нагревается ожидаемо.
5. Проверить в Engineer's Goggles два сопоставимых котла — вертикальный и горизонтальный — с одинаковыми условиями подачи воды и нагревателей. Учесть геометрию и число мест нагрева.
6. Если результат хуже/неверный: остановить сервер, вернуть резервную копию и провести исследование; не менять множитель выходной мощности автоматически.

Для Windows есть скрипт `tools/Set-ConnectedVesselHeat.ps1`. Он требует **явный путь** к TOML, не ищет и не меняет серверы самостоятельно, создаёт бэкап, меняет только одно значение.

Пример запуска из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Set-ConnectedVesselHeat.ps1 -ConfigPath "D:\\MyTestServer\\world\\serverconfig\\create_connected-server.toml"
```

Это **пример пути**, не путь к настоящему серверу.

## Почему изменения пока нет у игроков

Этот GitHub-репозиторий раздаёт лаунчер и манифест клиентских модов. Добавление документа и скрипта **не меняет серверный TOML**, не устанавливает новый мод и не публикует новое обновление. Нужно отдельно внести настройку в действующую серверную конфигурацию или добавить управляемое развертывание конфигов после проверки.
