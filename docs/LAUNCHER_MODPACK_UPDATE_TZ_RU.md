## 1. Аудит настоящей сборки, не названий файлов

Minecraft 1.21.1 / NeoForge 21.1.248. В сохранённом игровом каталоге владелец прислал **108 модов**, среди них Create 6.0.10, Sable 2.0.5, Create Aeronautics 1.3.2. В GitHub есть **два разных** источника:

- GitHub Release launcher-1.4.17 / player-mods-1.4.17.json — **108 модов**, реально предназначен для более нового лаунчера.

**Нельзя заменять релизный каталог более старым main-файлом.** Найди точный URL, который использует опубликованный лаунчер, и реальный набор на игровом сервере и у игроков. Создай инвентарную таблицу: файл → настоящий mod ID → версия в метаданных JAR → фактический код/сборка → актуальная совместимая версия у разработчика → сервер/клиент → зависимости → SHA-256 → URL → решение. Проверить наличие JAR у игроков, дубликаты, битые ссылки, конфликт версий и реальные различия между двумя манифестами.

**Отдельно по словам владельца: «дип ста»** (название распознано неуверенно). Упоминания с таким буквальным названием в предоставленном JSON нет. Искать по реальным JAR в рабочей сборке, старых каталогах, исходниках и логах. Выяснить, почему отображается как старая серия/версия, хотя содержимое выглядит новым: проверить mod ID, jar manifest, neoforge.mods.toml, embedded metadata, POM/version, sha256 и git history. **Не угадывать название и не устанавливать произвольный похожий мод.** Если идентификация невозможна, запросить точное имя файла.

На изолированном сервере протестировать неправильную/нестандартную геометрию (Г-образный, ступеньки, пустоты), воду/лаву/модовую жидкость, Create насосы и трубы, объединение/разделение, границу чанка, save/reload, взаимодействие с Aeronautics/Sable кораблём. ## 3. Codex вправе исправлять, но обязан проверять

1. Сначала **сделать backup** фактического мира, сервера, модов, конфигов, контрольных сумм и текущего канонического манифеста; никакой очистки рабочих каталогов и массовой замены.
2. По одному обновлять и чинить в **изолированной тестовой копии**. Собственные моды можно исправлять по исходникам; чужие — тестовые локальные патчи только с учётом лицензии и прав на распространение; предпочтительны upstream fixes. Проверить зависимости, миксины, NeoForge и совместимость с модами сборки.
3. Тесты: отдельный клиент и сервер, обычный пользователь и администратор, сборка Create, Sable/Aeronautics, новые механизмы, сохранение/перезагрузка мира, лог отсутствия ошибок, MSPT/память. Не утверждать, что проверено, если нет логов/результата.
4. **Только после испытаний** подготовить новый версионированный манифест, SHA-256/size/URL, корректные client/server требования, обновления лаунчера и управляемое удаление устаревших дублей. Не перезаписывать оригинальный опубликованный release манифест вслепую; убедиться, что реальный лаунчер читает новый адрес. Не переливать чужие моды в свой GitHub при запрещающей лицензии.
5. **Не смешивать задачу обновления модов с сетью Нади.** У Ани из РФ вход восстановился; у Нади оставались TLS/Discord проблемы и запущенный Zapret; в Польше 05.11 публичный и локальный HTTPS /status работал через Caddy и сообщал Guard 0.2.1-local.3-admin.1. SSL reset не объясняется автоматически старым JAR. Детали в архиве: LAUNCHER_GUARD_HTTPS_HOTFIX_TZ_RU.md.
6. Итог Codex: короткий отчёт **мод → обнаружено → версия/фикс → результат игрового теста → коммит → готовность к развёртыванию**, отдельный список блокирующих вопросов. Продуктивные сервер, мир, аккаунты, Guard, HTTPS/Playit и опубликованные файлы не менять без явного согласования владельца.
